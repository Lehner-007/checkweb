checkweb – Website diagnostics

Check local project files or online HTTP/HTTPS pages. Scans do not alter target files or submit forms.

Start a scan

  1. Select a local project directory or enter an online URL.
  2. Select checks. Missing tools are disabled; the Tools window shows package names.
  3. Start the scan. Cancel keeps partial results and labels them accordingly.
  4. Filter by severity or text and select a finding for its location and recommendation.
  5. Save a report using the .html or .json extension.

Checks

HTML5 structure, CSS parsing, JavaScript/PHP syntax, JSON/XML/SVG, references, HTTP responses, images, metadata, headings, encoding and basic automated accessibility checks. Security and performance checks provide contextual hints, not certification.

PHP syntax is checked locally only. Online checks cannot inspect private server-side PHP source. JavaScript is syntax-checked, not executed in a browser. Dynamic routes and content generated by JavaScript require additional manual review.

Scope and network

Internal links are followed within page/depth limits. External websites are not recursively crawled. Linked resources and external link checks cause network requests, including from local scans. Disable external link checking for offline-only scans. robots.txt is respected by default. Cross-origin redirects are reported rather than followed; use the final address as a separate start URL.

Positive settings limit request count, time, page count and depth. Zero removes the respective limit; the size limit per resource remains active. Limit findings mark incomplete coverage. A finished run does not mean every file or security property was checked. HTTP 429 stops further requests to that server for this run.

Tools

The base uses GTK 4/PyGObject, Beautiful Soup, requests and html5lib. tinycss2 parses CSS, lxml parses structured documents, and Pillow checks images. PHP and Node run in syntax-check mode only. Missing dependencies are reported, never installed automatically. Node 18 does not support every newer JavaScript feature; assess syntax findings against the intended runtime.

Reports

HTML is readable offline. JSON also includes check statuses, options and categories. Reports contain paths and URLs; review personal details before sharing. Unavailable and inapplicable checks are distinct from executed checks.

Languages and help

German and English are bundled. The initial language is German; English is the fallback. Import custom JSON language packs containing code, strings and help_html. Existing packs are not overwritten. Additional packs can later be downloaded from the fixed GitHub project source: BASE/fr.json. Sources are configured internally; local imports remain available.

Settings and updates

start.sh uses the project's .config directory. Direct startup uses ~/.config/checkweb. Save applies settings; language changes take effect immediately without restarting. Version checks run at every startup and never install updates. The internal version JSON contains {"program_id":"checkweb","version":"1.3.0"}; monthly intervals mean 30 days.

Limitations and privacy

Manual review is still needed for keyboard access, contrast, business logic and comprehensive security. Source and reports are not uploaded to external validation services. Local project code is not executed. Recognition of every web technology and every syntax/runtime problem is not guaranteed.

Menus and file selection

The menu bar provides File, Checks and Help. Online addresses without a protocol use https://; explicit http:// is preserved. Folder and save dialogs start in an existing directory. A missing report extension is added using the selected format. Missing tools are displayed in the main window and logged.

HTTP assessment and grouped reports

404/410: confirmed missing target according to the target server. 401/403: authentication or access restriction; check manually. 429: rate limit; retry later. 5xx or timeout: temporary or inconclusive result. Normal redirects are not errors. Targets blocked by robots.txt are marked as not checked. Missing compression, Cache-Control or CSP remain informational.

Reports show a summary, errors, warnings, manual reviews, notes, unchecked areas, redirects and technical details. Similar messages are grouped; expand occurrences in HTML or select a group in the app to read its sources. Resource and page limits are prominently labeled Scan incomplete. JSON retains all findings and records reached limits in the limits field.

Settings and menus

Select all checks enables available checks; Clear check selection removes their selection. Help contains Open user guide and About checkweb with version, author, license and logo.

Cancel and Save settings remain visible at the bottom of the settings window. The settings above them can be scrolled. Cancel discards edits. Every X days/weeks/months applies only to automatic checks for new application versions. One month equals 30 days. It does not schedule website scans.

Input and scan summary

Clear input empties the URL/folder field and is disabled during a scan. Reports show start, end and duration. Known targets are counted uniquely: known = conclusively checked + pending. Pending includes partial and inconclusive results. HTTP requests and started content analyses are separate counts. Undiscovered pages remain unknown.

Internal online targets share the scan target’s hostname; other hostnames are external. Errors show their source and destination. Result groups count individual findings. Pending targets, failed tools or reached resource, page and depth limits make a scan incomplete.

Unlimited test scans and log editor

Zero means unlimited for page count, link depth, files/HTTP requests and timeout. Positive settings still apply limits. Cancellation also works without a timeout, keeping partial results. robots.txt, cross-origin redirect rules and the size limit per resource remain active.

Help → Open / edit log displays the current application log for viewing and editing. Reload and Save log are explicit actions. If new log entries have arrived, saving is rejected until reloading, protecting those entries.

Website errors, external links and resources

The summary separately counts website errors, broken external links/resources, manual review (401/403), inconclusive results (including timeout, 429, 5xx and robots.txt), warnings, hints and redirects. An external 404/410 is not a technical failure of the checked website. Source, line, available link text, target and HTTP status are retained. 403 requires browser review. Inconclusive does not mean broken or unreachable; incomplete scans explain what remains unchecked.

Technical details group resources into HTML, CSS, JavaScript, images, fonts and XHR/fetch, showing URL, HTTP status, embedding source and internal/external scope. Nested CSS imports and relative paths are resolved. Literal fetch URLs without options and XHR with literal GET/HEAD targets can be identified statically. Dynamic URLs and runtime content require browser review. JavaScript is not executed; browser-internal messages and other tabs are never assessed.

Application version 1.3.0

The window title shows the version. Open tools from Help → Info. Settings are under File between visible separators; the user guide and log editor are under Help. About displays the checkweb image. Defaults: 100 pages, link depth 3, 300 files/HTTP requests and 10 seconds per request/tool. 0 remains available to remove each of these limits.

After extracting the release ZIP, start python3 checkweb.py. Eight additional language packs with help are distributed separately: Arabic, Spanish, French, Hindi, Portuguese, Russian, Turkish and Simplified Chinese. Import the JSON pack in Settings, select the language, save; the language changes immediately without restarting. A GitHub download source is available only after publication.

Language packs and version documents must contain "program_id": "checkweb" at the top JSON level. Missing or foreign identifiers are rejected before applying data. Older packs without this field must be updated before importing again; installed languages are preserved. The identifier assigns the project; it is not proof of authenticity.

New application log entries immediately follow the selected language. Existing entries remain unchanged; third-party technical messages keep their original wording.

Consistent appearance

Settings are under File, between visible separators. Language selection, import and download are grouped under Additional languages and help. Start, cancel, export and check selection are accessed through the menus. The centered progress window shows the current task and Cancel, and closes when work finishes. Results have alternating row backgrounds. The existing log editor is under Help. New log sessions have visible separators; previous entries are preserved.

Storage

Report exports cannot overwrite application resources or active settings, including through symbolic links. The interface replaces existing normal reports only after confirmation. The CLI output parameter replaces normal reports directly; protected targets are rejected with a message.

Press F5 to start a check. It invokes Checks → Start check and is disabled while an operation is running.

Uninstallation

Uninstallation removes known Checkweb user data. The installed application records the XDG locations it uses. Personal unmarked launchers are retained. Root/system accounts, inaccessible homes and linked parent directories are excluded. Cleanup failures are reported without blocking package operations. Before removing the package, users can run checkweb-cleanup --user remove without sudo; this deletes settings and personal language packs. Reports and downloads are retained.

Updates / Info

Updates are checked at every startup. File → Settings shows the software status. Download update saves a newer DEB in Downloads and verifies SHA-256, package name, version and architecture. Cancel removes incomplete downloads. Existing different files remain untouched. Installation remains manual. GitHub sources are fixed internally. Help → Info shows tools and package names.

Additional online diagnostics

The selectable Additional online diagnostics group compares HTTP/HTTPS and www/non-www variants, probes a random nonexistent address and reads /sitemap.xml. Every request shares the budget, robots.txt, cancellation, time and byte limits. Cross-origin redirects are reported as boundaries. Soft 404, differing variants and canonical/sitemap contradictions remain hints. robots.txt comparison covers at most 20 sitemap URLs; sitemap indexes are not followed. DNS, connection, TLS and HTTP failures are distinct. Reports list executed and unchecked tests with reasons and possible login pages. Local scans do not run these additional online requests.
